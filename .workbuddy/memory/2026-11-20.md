## 修 CI 归档 19（GPU 归档）失败

- 现象：run 44685831803 中 `build-hummer-adreno-kits.py` 编 `NativeAdrenoGmuContext.cpp` 时
  `NativeAdrenoSmmuMemory.h:16: unknown type name 'ArmSmmu4KTablePages'`，kernel.macho 未产出。
- 根因：引擎 d9460ebb 把 `kits/ArmSmmu4K` 钉在 4d0d659（旧 live arena 自带 table pool），
  而 `drivers/NativeAdreno` 的 pin a9a2cbb（2026-11-01）按需分配表页、用
  `ArmSmmu4KTablePages`（48dbd6c / 2026-10-28 引入）。只前移驱动不够，kit 要一起走。
- 修法：`unixnu` 里加 `kit_revisions = {'ArmSmmu4K': '83969cd...'}`（= UniXNU main 的 pin），
  子模块前移循环抽象成 drivers/ + kits/ 共用；指纹纳入 kit_revisions；内部 pin 提交加
  `-c commit.gpgsign=false`（本机开签名会让 prepare 卡 gpg 超时）。
- 本地用 `./unixnu --prepare` 验证过：两个子模块都到目标 commit、驱动/固件补丁都应用、
  `kits/ArmSmmu4K/*.c` 在 Linux clang 下语法通过（Mmio.c 因非 AArch64 报 #error，正常）。
- 提交 8a8cb67 已推 origin/main，新 run 44688944767 触发。

## 构建路径备忘

- 内核/payload 只能在 macOS 或 CI（macos-15）编；本机 CachyOS 只能跑 prepare。
- 仓库是 fork（venti1112/UniXNU-hummer ← 2426120557/UniXNU-hummer），fork 的 Actions 需手动启用。
- boot 镜像在 WSL 里 `bash dopack.sh <ver> <tag>`，脚本不在仓库。
